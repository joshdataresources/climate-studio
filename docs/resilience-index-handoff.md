## The goal
Turn the app from a set of separate hazard overlays into an **Environmental Resilience Index**: a
decision tool that ranks US metros by how well they hold up to a changing climate. Resilience =
**hazard exposure** (how bad the hazards get) balanced by **adaptive capacity** (whether the city
can/will fortify), scored 0–100 (higher = more resilient), tracked by decade to 2100. The map stays
the centerpiece; the index adds a resilience layer + a leaderboard + dashboard data viz. Keep the
map viewer — this is additive, not a rewrite.

## Data provenance & caveats (do not gloss over these)
- Heat = NASA NEX-GDDP-CMIP6, generated by Earth Engine scripts in `qgis-processing/`
  (`regenerate_wet_bulb.py` etc.). 52 metros, ssp585. Real.
- Water river-flow declines are **literature-parameterized regional rates** (USGS / Bureau of
  Reclamation / EPA), not per-river model output — see `scripts/fetch-river-flow-projections.py`.
  Only **~19 of 52 metros** map to a river with real data; the other ~33 use a placeholder default.
- Aquifers are a **stub** (a flat −10 penalty on Oklahoma City + Memphis). `aquifer-projections.json`
  lists ~66 aquifers but only 3 have usable numbers.
- Known app issue (not blocking the index): the wet-bulb *map* layer reverse-engineers a fake temp
  (`estimatedSummerTempF = 90 + days_over_95F/20`) instead of using the real stored value; the
  scatter chart uses the real value. The index deliberately uses the real fields.

## CURRENT TASK — add fire, flood, and adaptive capacity via FEMA National Risk Index
Only heat + water are in the repo. Fire, flooding, and capacity are **not** — pull them from one
authoritative source: **FEMA National Risk Index (NRI)**, per-county.

**Confirmed endpoint (ArcGIS FeatureServer):**
`https://services.arcgis.com/XG15cJAlne2vxtgt/arcgis/rest/services/National_Risk_Index_Counties/FeatureServer/0/query`

**Confirmed fields (verified against Harris County, TX / STCOFIPS 48201):**
- `STATE` ("Texas"), `COUNTY` ("Harris"), `STCOFIPS` ("48201"), `POPULATION`
- `RISK_SCORE` (composite, 0–100 national percentile), `RISK_RATNG`
- Hazard risk scores (0–100 percentile, higher = worse): `WFIR_RISKS` (wildfire),
  `IFLD_RISKS` (riverine flood — NRI calls it **Inland** Flooding, NOT `RFLD`),
  `CFLD_RISKS` (coastal flood), `HWAV_RISKS` (heat wave), `DRGT_RISKS` (drought).
  Suffix convention: `_RISKS` = risk index score (use this), `_RISKR` = rating,
  `_EALT` = expected annual loss. Confirmed `_RISKS` fields on the layer include: AVLN, CFLD,
  CWAV, DRGT, ERQK, HAIL, HWAV, HRCN, ISTM, LNDS, LTNG, IFLD, SWND, TRND, TSUN, VLCN, WFIR, WNTW.
  If unsure, read the field list at `.../FeatureServer/0?f=json` (fields[].name).
- `RESL_SCORE` (Community Resilience, 0–100, higher = MORE resilient) — this is the "likely to
  fortify" / adaptive-capacity dimension. Also `RESL_RATNG`, `RESL_VALUE`.
- `SOVI_SCORE` (Social Vulnerability, higher = MORE vulnerable), `SOVI_RATNG`

**Scoring direction when folding into the index (higher = better):** invert hazard scores
(`100 − WFIR_RISKS`, etc.) and invert SOVI; use `RESL_SCORE` as-is.

**Fetch gotchas (important):** `web_fetch` has a max URL length AND a max response size.
- `outFields=*` returns ~400 fields (~89 KB) per county — too big. Use a SHORT explicit `outFields`
  list (only the ~12 fields above).
- A long `outFields` list + long `where` also blows the URL-length limit. Balance: query a handful
  of counties per call with a modest field list, or query by state. Consider the ArcGIS
  `resultOffset`/`resultRecordCount` paging (max 2000/records).
- Map each of the 52 metros to its principal county. Cleanest: spatial point query per metro using
  its lat/lon (`geometry=lon,lat&geometryType=esriGeometryPoint&spatialRel=esriSpatialRelIntersects`)
  to avoid county-name mismatches — metro lat/lon are in `expanded_wet_bulb_projections.json`.
- Do NOT fetch via curl/wget/python — only the provided `web_fetch`/`WebSearch` tools.
