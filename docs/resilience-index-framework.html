The Environmental Resilience Index

A decision tool that ranks US metros by how well they hold up to a changing climate — not a map of danger, but a comparable, defensible score that tells you where to live, build, and invest.

Draft framework · 52 metros · projections to 2100 · heat live · water prototype · fire / flood / capacity live (FEMA NRI) · weights tunable

The idea in one line

Environmental resilience is hazard exposure (how hard the climate hits a city) balanced against adaptive capacity (how well the city can absorb it), measured every decade to 2100. Climate Studio already has the hard part most tools skip — the time axis — so the job is to turn per-hazard layers into one comparable ranking.

Every new dimension plugs in identically: measure → normalize → weight. The index grows without re-architecting.

Scoring method

Each indicator becomes a 0–100 sub-score where 100 = most resilient. For a hazard, higher raw hazard means a lower score:

hazard   = 0.5 · norm(peak_wet_bulb) + 0.5 · norm(extreme_heat_days)
score    = 100 − hazard                       // 0–100, higher = better
norm(x)  = (x − min) / (max − min) · 100       // min/max across all metros

Normalizing on a fixed scale (across all cities and all decades) matters: it keeps rankings comparable and lets a city's absolute decline show up, rather than hiding it behind a per-year re-normalization.

Weighting — now tunable, not buried in code. The engine takes a ResilienceWeights object: a relative weight per hazard dimension (heat, water, fire, flood) plus a capacityShare blend between exposure and adaptive capacity. Defaults: equal hazard weights, 60/40 exposure-to-capacity. The Dashboard leaderboard exposes all five as live sliders, so stakeholders can challenge the numbers by moving them. Hazard weights are normalized over whichever dimensions a metro actually has, so a missing dimension never silently zeroes a score.

Trajectories to 2095

On a fixed scale, the average metro loses ~25 points (65.6 → 40.9, 2025→2095). Marine California declines slowest (San Jose 96→81); Gulf and desert metros fall off a cliff (Miami 62→17, Phoenix 40→16). Rankings also reshuffle — Salt Lake City slips from #1 to #6 as extreme-heat days accumulate, and San Jose / San Francisco inherit the top. Resilience is a moving target, which is exactly why the decade axis matters.

Dimension 2 — water access (portfolio model)

Water is now scored as access: each metro's utility-documented supply portfolio (metro-water-access.json, researched and cited per metro from utility/state sources, ~2024–25 mixes) is weighted by share across six source types — river, reservoir, groundwater, imported, desalination, recycled. Each source carries its own climate health: river- and reservoir-fed sources inherit the matched river's projected flow decline (Colorado-basin imports like CAP, SNWA, and QSA transfers inherit the Colorado's decline minus a conveyance-risk margin), Great Lakes intakes count as deep buffered storage, groundwater inherits the spatial aquifer join's stress class, and desal/reuse are near climate-independent. NYC's protected reservoirs score ~96 while Tucson's CAP-recharged basin supply scores ~48 — the same score now means the same thing everywhere: "how well does what this city actually drinks hold up."

Groundwater is now spatial, not a stub. Each metro is point-in-polygon joined against the app's USGS principal-aquifer polygons (scripts/build-metro-aquifers.py → metro-aquifers.json), classified by stress (dataset recharge-vs-consumption fields + documented overrides like Biscayne saltwater intrusion and Houston subsidence), and scaled by documented municipal dependence — being over an aquifer is not the same as drinking from it. Metros over no productive aquifer (Raleigh, on Piedmont crystalline rock) get no adjustment; sole-source groundwater cities (Memphis, Miami, Nassau County) feel their aquifer's stress at full weight; surface-supplied cities over stressed aquifers (Oklahoma City, Denver) barely notice it. This replaced a flat −10 penalty that hit only OKC and Memphis.

Provenance — read before trusting. The river flow-decline figures are literature-parameterized regional rates (USGS, Bureau of Reclamation, EPA, Colorado River studies) applied to curated 2025 baselines and interpolated by decade — not raw per-river climate-model output. Directionally sound and transparent, but label it as an estimate. (Separately, the live precipitation service currently runs on CHIRPS as a proxy, not the intended NOAA LOCA2.)

Coverage is the real constraint

Heat is uniform — the NASA grid covers all 52 metros identically. Water isn't. Only ~19 of 52 metros map to a river with real projection data; the other ~33 fall back to a placeholder default. Those fallbacks are the weakest part of the prototype and the top data task before any public ranking. There is no repo source for the missing metros — closing the gap needs external supply data, not a heavier formula.

Dimensions 3–5 — fire, flood, adaptive capacity (FEMA NRI, live)

Three dimensions come from one authoritative source: the FEMA National Risk Index (NRI 2.0), fetched per principal county for all 52 metros (county resolved by spatial point query on each metro's coordinates, so no name-matching errors). Stored in src/data/fema_nri_metros.json; scored in resilienceScore.ts:

fire     = 100 − WFIR_RISKS                              // wildfire risk percentile
flood    = 100 − max(IFLD_ALR_NPCTL, CFLD_ALR_NPCTL)     // EAL *rate* percentiles; null coastal = no exposure
capacity = ½ · RESL_SCORE + ½ · (100 − SOVI_SCORE)
composite = (1 − capacityShare) · Σ wᵢ·hazardᵢ / Σ wᵢ  +  capacityShare · capacity

NRI 2.0 renamed riverine flooding: the field is IFLD_RISKS ("Inland Flooding") — there is no RFLD. RESL_SCORE is Community Resilience (higher = better, used as-is); SOVI_SCORE is Social Vulnerability (higher = worse, inverted).

Two caveats worth keeping visible. ① NRI is a present-day snapshot: fire, flood, and capacity are held flat across projection decades while heat and water carry the time trend. A 2095 composite mixes 2095 heat with 2026 wildfire. ② Magnitude vs. rate: NRI *_RISKS scores are percentiles of expected-annual-loss magnitude, which scale with exposed population and property — on inland flood they pinned every big-metro county at ~100, leaving the flood sub-score between 0 and 17 (median 2, pure dead weight). Flood therefore uses the EAL-rate percentiles (IFLD_ALR_NPCTL / CFLD_ALR_NPCTL), which normalize out exposure; the sub-score now spans ~5–95 (median ~45). Fire still uses WFIR_RISKS — its spread (0–91) is already adequate.

What the new dimensions change (2055, default weights)

The sanity checks pass: wildfire drags the West (fire-only ranking bottoms out at Colorado Springs, Phoenix, Tucson, LA, San Diego — San Diego's WFIR is literally 100); the rate-based flood dimension flags flash-flood and coastal loss-rate hotspots (worst: Tucson 5, Los Angeles 5, San Jose 5, Houston 15, Merrick/Nassau 14; best: Salt Lake City 95, Cincinnati 76, Minneapolis 74) rather than merely-populous counties; capacity lifts low-vulnerability metros (Minneapolis 89, Raleigh 88, Seattle 86). One result cuts against intuition: New York's capacity is only 36 — Manhattan's Social Vulnerability percentile is 96, swamping its decent Community Resilience score. County granularity is doing real work there (Merrick/Nassau County scores 86), which is an argument for metro-level aggregation later, not a bug in the pipeline. With all five dimensions live, the 2055 top tier is Portland, Minneapolis, Milwaukee, San Francisco, Salt Lake City; the bottom is San Antonio, Las Vegas, Phoenix, Houston, Tucson — exposed on several axes at once with little capacity to compensate.

Data model

A single shape carries an indicator from raw measurement to normalized sub-score, so exposure and capacity are handled uniformly:

// One indicator, from raw numbers to a 0–100 sub-score
interface IndicatorScore {
  key: 'heat' | 'water' | 'flood' | 'wildfire' | 'air' | 'storms'
      | 'waterSupply' | 'infrastructure' | 'economy' | 'cooling'
  raw: Record<string, number>   // underlying measurements (e.g. peakWetBulbF)
  score: number                  // normalized 0–100, 100 = most resilient
  status: 'live' | 'planned'
}

// Shipped in resilienceScore.ts — five live sliders in the leaderboard
interface ResilienceWeights {
  heat: number                   // relative hazard weights,
  water: number                  // normalized over the dimensions
  fire: number                   // a metro actually has
  flood: number
  capacityShare: number          // 0–1 exposure↔capacity blend, default 0.4
}

interface CityResilienceScore {
  metroKey: string
  name: string
  lat: number
  lon: number
  year: number                   // decade, 2025…2095
  exposure: IndicatorScore[]
  capacity: IndicatorScore[]
  composite: number              // final 0–100 resilience score
  rank: number                   // 1 = most resilient that year
}

// city key → year → score
type ResilienceProjection =
  Record<string, Record<number, CityResilienceScore>>

What's next

  • Close the water coverage gap. Highest priority: map the ~33 unscored metros to a real supply source so the composite means something everywhere, not just the 19 river-linked cities.
  • Ground the flow numbers. Confirm or replace the literature-parameterized river declines with modeled streamflow, and wire the precipitation service to real LOCA2 instead of the CHIRPS proxy.
  • Retire the heat proxy. The index needs one trustworthy wet-bulb number per city — building it forces the fix for the map/chart discrepancy from the code review.
  • Put resilience on the map. The engine already exposes resilienceColorRGBA() + rankMetros(); the blocker is architectural — the layer registry assumes server-fetched layers, so a client-computed layer needs a small new path (decide approach before wiring it).
  • Sharpen the FEMA dimensions. Flood now uses rate-based *_ALR_NPCTL percentiles (done — see caveat ②). Remaining: metro-level aggregation instead of a single principal county (the Manhattan SOVI effect), and a forward-looking trend on fire/flood instead of holding them flat to 2100.
