# Data provenance

What every dataset the app ships is, where it came from, and which parts are not
real. Written because the answer was scattered across generator-script docstrings
and a handoff note, and because two fabricated values had reached the UI without
anyone being able to tell by looking.

## Real

| Dataset | Source |
|---|---|
| `metro_temperature_projections.json` | NASA NEX-GDDP-CMIP6 via Earth Engine, 52 metros. Generated by `qgis-processing/regenerate_metro_temps.py`, which replaced an earlier latitude-bucket estimator. Verified real: 51 distinct baseline triplets across 52 cities, where the estimator produced three. |
| `expanded_wet_bulb_projections.json` | NASA NEX-GDDP-CMIP6, ssp585, via `qgis-processing/regenerate_wet_bulb.py`. Humidity, wet-bulb events and day counts computed per city per decade; wet-bulb temperature from daily `tas` and `hurs` using the Stull (2011) formula. |
| `fema_nri_metros.json` | FEMA National Risk Index 2.0, fetched July 2026. Has its own `_meta` block. Regenerable via `scripts/merge-nri-parts.py`. |
| `metro-aquifers.json` | Spatial join of metro coordinates against the app's USGS principal-aquifer polygons, built by `scripts/build-metro-aquifers.py`. Its method, including the curated municipal-dependence table, is documented in that script's docstring. |
| `metro-water-access.json` | Utility-documented supply mixes, researched and cited, ~2024-25. |
| Sea level rise figures | NOAA Technical Report NOS 01 (2022), GMSL scenarios. See `src/config/climateProjections.ts`. |
| Temperature anomaly figures | IPCC AR6 WG1, Table SPM.1 best estimates. Same file. |
| Map raster layers | Served live: NOAA Sea Level Rise Viewer, USFS Wildfire Hazard Potential, and Earth Engine imagery. Fetched by the browser direct from source. |

## Not real, and not displayed

`expanded_wet_bulb_projections.json` carries three fields its own generator
documents as fabricated and deliberately never computed:

    estimated_at_risk_population
    casualty_rate_percent
    extent_radius_km

They are absent entirely for some cities. Nothing renders them. They are typed
optional so it stays obvious they may not be there.

Two places had been using them, both now fixed:

- `DeckGLMap` sized its wet-bulb circles from `extent_radius_km`, and computed a
  wet-bulb temperature by reverse-engineering a dry-bulb one from the count of
  days over 95°F (`90 + days_over_95F / 20`). For Houston that produced 94.8°F
  where the dataset's own stored summer wet bulb is 81.0°F. It now reads the
  stored value and sizes circles from event counts and metro population.
- `MetroUnifiedPopup` displayed "Est. Pop. in Zone" from
  `estimated_at_risk_population`. It now shows peak wet bulb, which is measured.
  `MetroMapCard` had already omitted these fields for unverified provenance.

The Climate Projections panel used to show precipitation, drought index and soil
moisture built from invented constants. They are not displayed; none had a source
and none is meaningful as a single global figure. To restore them, read the
precipitation-drought service for the current viewport the way the map layer does.

## Unverified

`aquifers.json` — the polygons are USGS principal aquifers, but the per-aquifer
`volume_gallons_2025` and its `projections` series carry no recorded source and no
generator script in this repo. Treat those numbers as unverified until someone
establishes where they came from.
